# 04.md — Development Step 4: Data Quality Tab

## Goal

Implement the **Data Quality** tab.

The dashboard already supports:

```text
Step 1: Upload + preview + column profiling
Step 2: Survival role candidate detection + confirmed survival mapping
Step 3: Basic Kaplan–Meier survival analysis
```

Step 4 should make the dashboard safer and more trustworthy by checking whether the uploaded dataset has quality issues that could affect downstream analysis.

The Data Quality tab should answer:

```text
Can this dataset be trusted for exploratory survival analysis?
Are there duplicate rows?
Are there duplicate patient IDs?
Are there missing values?
Are survival time and event/status values valid?
How many rows were excluded from survival analysis?
Are selected groups too small or too fragmented?
Are there possible sensitive identifier columns?
```

This step should **not clean or modify the dataset automatically**. It should detect and report issues.

---

## Expected Outcome

After Step 4, the Data Quality tab should show:

```text
1. Dataset quality summary cards
2. Overall quality status
3. Missingness by column
4. Missingness by row
5. Duplicate row check
6. Duplicate patient ID check, if patient ID is selected
7. Survival-specific quality checks, if survival mapping exists
8. Grouping-quality checks, if group column exists
9. Possible identifier / sensitive-column warnings
10. A structured issue table with severity levels
```

Example UI output:

```text
Data Quality

Overall status: Warning

Rows: 228
Columns: 10
Total missing cells: 67
Duplicate rows: 0
Duplicate patient IDs: Not checked — no patient ID selected
Usable survival rows: 228
Excluded survival rows: 0

Warnings:
- No patient ID column selected; row number is being used.
- Column meal.cal has 20.61% missing values.
- Group values are numeric-coded. Consider adding labels.
```

# 5. Quality Issue Data Model

In `src/data_quality.py`, define a small structured issue format.

Use a dataclass:

```python
from dataclasses import dataclass, field
from typing import Any, Optional

@dataclass
class QualityIssue:
    severity: str
    category: str
    message: str
    affected_columns: list[str] = field(default_factory=list)
    affected_rows_count: Optional[int] = None
    details: dict[str, Any] = field(default_factory=dict)
```

Allowed severity values:

```text
error
warning
info
```

Meaning:

```text
error:
    A blocking issue that makes survival analysis invalid or unsafe.

warning:
    A non-blocking issue that may affect interpretation.

info:
    Useful quality note.
```

Examples:

```python
QualityIssue(
    severity="warning",
    category="duplicates",
    message="Selected patient ID column contains duplicate values.",
    affected_columns=["patient_id"],
    affected_rows_count=12,
    details={"duplicate_id_examples": ["P001", "P044"]}
)
```

Definitions:

```text
complete_rows_percent = complete_rows / n_rows * 100
```

If dataframe is empty, avoid division by zero.

## 11.1 Time Column Checks

Using the raw uploaded dataframe and `survival_config.time_col`, check:

```text
time_col exists
time values can be parsed as numeric
missing time values
non-numeric time values
negative time values
zero time values
```

Issue rules:

```text
Missing time values:
    warning

Non-numeric time values:
    error if any remain after parsing

Negative time values:
    error

Zero time values:
    warning
```

Negative time should be blocking because survival time cannot be negative.

Zero time is not always invalid, but it should be flagged because it may indicate same-day event, encoding issue, or bad data.

---

## 11.2 Event Column Checks

Using the raw uploaded dataframe and `survival_config.event_col`, check:

```text
event_col exists
missing event values
values mapped to event
values mapped to censored
unmapped non-missing values
```

Issue rules:

```text
Missing event values:
    warning

No event values selected:
    error

Event/censor values overlap:
    error

Unmapped non-missing event values:
    warning

No events:
    warning

No censored rows:
    warning
```

Unmapped non-missing values are values in the event column that are neither in:

```text
survival_config.event_values
survival_config.censor_values
```

## 13.2 Value-Based Detection

For object/text columns, check a sample of non-missing values.

Flag:

```text
Email-like values:
    contains pattern similar to something@example.com

    average string length > 80
```

Risk levels:

```text

    high

phone-like values:
    high

    medium
```

Do not overfit this. Keep it lightweight.
